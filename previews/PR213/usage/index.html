Usage

The FixedSizeArray type

Constructors

The basic type provided by this package is FixedSizeArray. Its constructor uses a similar syntax to Base's Array:

julia> using FixedSizeArraysjulia> v = FixedSizeArray{Float64}(undef, 3)3-element FixedSizeArrays.FixedSizeArrayDims{Float64, 1, Tuple{Int64}, Memory{Float64}}: 1.5e-323 1.6e-322 6.9117173452141e-310julia> M = FixedSizeArray{Float64}(undef, 2, 2)2×2 FixedSizeArrays.FixedSizeArrayDims{Float64, 2, Tuple{Int64, Int64}, Memory{Float64}}: 1.6e-322      5.0e-323 6.91172e-310  1.43e-322

You can also construct FixedSizeArrays from other arrays:

julia> using FixedSizeArraysjulia> arr = [10 20; 30 14]2×2 Matrix{Int64}: 10  20 30  14julia> FixedSizeArray(arr)  # construct from an `AbstractArray` value2×2 FixedSizeArrays.FixedSizeArrayDims{Int64, 2, Tuple{Int64, Int64}, Memory{Int64}}: 10  20 30  14julia> FixedSizeArray{Float64}(arr)  # construct from an `AbstractArray` value while converting element type2×2 FixedSizeArrays.FixedSizeArrayDims{Float64, 2, Tuple{Int64, Int64}, Memory{Float64}}: 10.0  20.0 30.0  14.0

To "convert" a wrapper type like Adjoint while preserving the wrapper structure, you can use Adapt:

julia> using FixedSizeArrays, Adaptjulia> arr = transpose([10 20; 30 14])2×2 transpose(::Matrix{Int64}) with eltype Int64: 10  30 20  14julia> adapt(FixedSizeArray, arr)2×2 transpose(::FixedSizeArrays.FixedSizeArrayDims{Int64, 2, Tuple{Int64, Int64}, Memory{Int64}}) with eltype Int64: 10  30 20  14

For 1- and 2-dimensional arrays you can use the aliases FixedSizeVector and FixedSizeMatrix, respectively:

julia> using FixedSizeArraysjulia> v = FixedSizeVector{Float64}(undef, 2)2-element FixedSizeArrays.FixedSizeArrayDims{Float64, 1, Tuple{Int64}, Memory{Float64}}: 0.0 5.0e-324julia> M = FixedSizeMatrix{Float64}(undef, 3, 3)3×3 FixedSizeArrays.FixedSizeArrayDims{Float64, 2, Tuple{Int64, Int64}, Memory{Float64}}: 1.8e-322   1.04e-321       6.91173e-310 2.27e-322  1.685e-321      0.0 3.16e-322  6.91169e-310  NaN

The memory backend

The FixedSizeArray{T,N,Mem} type has three parameters:

  • T: the type of the elements of the array (e.g. Int64 or Float64);
  • N: the number of dimensions of the array (e.g. 1 for a vector, 2 for a matrix);
  • Mem<:DenseVector{T}: the memory backend.
Implementation details

In Julia v1.11+, the default memory backend is the Memory{T} type. Since Julia v1.10 does not have the Memory type, to make this package usable also on Julia v1.10 Vector{T} is used as memory backend, but many of the memory/performance optimizations enabled by this package will not be available in that version of Julia and in general FixedSizeArrays.jl does not provide significant improvements compared to Base's Array for that specific version.

To make it easier to refer to the concrete type FixedSizeArray{T,N,Mem} with the default memory backend, the following convenient aliases are available:

  • FixedSizeArrayDefault{T,N};
  • FixedSizeVectorDefault{T};
  • FixedSizeMatrixDefault{T}.

Static dimensions: the FixedSizeArrayDims type

Many arrays in numerical codes have a shape that is partly known in advance. Take the solution of a discontinuous Galerkin method in three dimensions, stored as u[variable, i, j, k, element]: the number of variables (five for the compressible Euler equations) and of nodes per direction (say four) are fixed by the choice of the equations and the polynomial degree, but the number of elements depends on the mesh, and may change while the simulation runs, e.g. with adaptive mesh refinement. With a plain Array or FixedSizeArray the compiler knows none of these sizes, so every index computation multiplies with sizes loaded from memory, and loops over the small dimensions cannot be fully unrolled.

For such arrays, the dimensions of the underlying type FixedSizeArrays.FixedSizeArrayDims{T,N,D,Mem} can be a tuple of type D of Ints and StaticInts from Static.jl. Any dimension can be static or dynamic. FixedSizeArray{T,N,Mem} is the alias FixedSizeArrayDims{T,N,NTuple{N,Int},Mem} with all dimensions dynamic, so all FixedSizeArrays are FixedSizeArrayDimss, but the arrays with static dimensions are not FixedSizeArrays. FixedSizeArrayDims is public, but not exported. Static.jl is a weak dependency of FixedSizeArrays.jl, so it is only loaded, and static dimensions are only available, once you load it yourself, e.g. with using Static: static. The static dimensions are part of the type, and take no space in the array, so the compiler can compute the sizes in these dimensions, and the strides and linear indices involving them, at compile time:

julia> using FixedSizeArrays: FixedSizeArrays, FixedSizeArrayDimsjulia> using Static: static, StaticIntjulia> nelements = 3;julia> u = FixedSizeArrayDims{Float64}(undef, (static(5), static(4), static(4), static(4), nelements));julia> size(u), strides(u)((5, 4, 4, 4, 3), (1, 5, 20, 80, 320))julia> size(u, 2)  # a compile-time constant4julia> typeof(u)FixedSizeArrayDims{Float64, 5, Tuple{StaticInt{5}, StaticInt{4}, StaticInt{4}, StaticInt{4}, Int64}, Memory{Float64}}

An array with static dimensions can also wrap an existing memory backend with FixedSizeArrays.wrap, without copying. At most one dimension can be given as :, which is then computed from the length of the memory backend, e.g. to wrap a Vector again after it was resized:

julia> using FixedSizeArrays: FixedSizeArrays, FixedSizeArrayDimsjulia> using Static: staticjulia> v = collect(1.0:12.0);julia> a = FixedSizeArrays.wrap(FixedSizeArrayDims, v, (static(2), static(3), :));julia> size(a), parent(a) === v((2, 3, 2), true)julia> b = FixedSizeArrayDims{Int}(undef, (5, static(3)));  # a static dimension after a dynamic onejulia> size(b)(5, 3)

The dimensions given to a constructor are converted to the dimensions type of the array, if its type gives it: e.g. FixedSizeArray{Float64}(undef, (static(2), 3)) has two dynamic dimensions, while FixedSizeArrayDims{Float64}(undef, (static(2), 3)) has a static one. similar(a), similar(a, T) and similar(typeof(a), size) keep the static dimensions, while similar(a, T, size) returns a FixedSizeArray with all dimensions dynamic, so that its type does not depend on the value of size. Out-of-place broadcasting, reshape and vec return FixedSizeArrays, too. With the package extension for StaticArrayInterface.jl, the static sizes and strides are available to packages such as LoopVectorization.jl, StrideArraysCore.jl and Polyester.jl. Unlike for FixedSizeArrays, Adapt.adapt adapts the memory backend of an array with static dimensions and wraps it again, e.g. adapt(CuArray, a) returns a FixedSizeArrayDims backed by a CuVector. FixedSizeArrayDims itself is not an Adapt.adapt target: adapt(FixedSizeArrayDims, x) returns x unchanged, since the static dimensions can not be derived from x; use the constructor, e.g. FixedSizeArrayDims{Float64, 2, Tuple{StaticInt{2}, Int}}(x), instead.

See the comparison with other array types for how FixedSizeArrayDims relates to StaticArrays.jl, HybridArrays.jl and StrideArraysCore.jl.

The collect_as utility

The array literals syntax [A, B, C, ...] to construct arrays is limited to Base's Array and cannot be extended to custom array types. The package Collects.jl provides a convenient function, collect_as, to overcome this limitation and construct FixedSizeArrays out of any iterable:

julia> iter = (i for i ∈ 7:9 if i≠8);julia> using FixedSizeArrays, Collectsjulia> collect_as(FixedSizeArray, iter)  # construct from an arbitrary iterator2-element FixedSizeArrays.FixedSizeArrayDims{Int64, 1, Tuple{Int64}, Memory{Int64}}: 7 9julia> collect_as(FixedSizeArray{Float64}, iter)  # construct from an arbitrary iterator while converting element type2-element FixedSizeArrays.FixedSizeArrayDims{Float64, 1, Tuple{Int64}, Memory{Float64}}: 7.0 9.0julia> collect_as(FixedSizeVectorDefault, (3.14, -4.2, 2.68))  # construct from a tuple3-element FixedSizeArrays.FixedSizeArrayDims{Float64, 1, Tuple{Int64}, Memory{Float64}}:  3.14 -4.2  2.68

See the Collects.jl Readme for more information.

BoundsErrorLight exception

To facilitate the escape analysis of FixedSizeArrays, accessing an out-of-bound index of these arrays raises a BoundsErrorLight exception when possible. This exception type does not store the entire array for reporting the error message, thus enabling more performance optimizations compared to arrays which throw BoundsError exceptions.

Compatibility of exception raised

We do not guarantee to throw either BoundsError or BoundsErrorLight when accessing an out-of-bound index of a FixedSizeArray. The exact exception raised may change at any point without breaking the semantic versioning compatibility contract.

Note

BoundsErrorLight is an alias for LightBoundsError from the LightBoundsErrors.jl package.
